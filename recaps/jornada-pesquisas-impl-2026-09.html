o que o sistema faz agora

O core: benchmark → apontar um prompt melhor — ou dizer que não melhorou

A promessa do produto fechada em código, com uma decisão de produto no topo: melhoria contínua não é objetivo. Plateau é resultado legítimo; o que nunca pode acontece é recomendar sem evidência.

03 · JULGAMENTO
Por referência

04 · ESTATÍSTICA
judge-score + IC
permutação exata (nunca p de bootstrap) · max-T melhor-de-K · reps agregadas por cenário
→
05 · DECISÃO
Recomenda OU recusa
n≥5 · IC sem cobrir 0 · P(A>B)≥80% · senão: “inconclusivo” com conta de poder

“Se o prompt não melhorar mais, tudo bem” — está codificado

O training convergencia por plateau (IC do ganho cobre minGain) ou paciência ≥ 2 e reporta convergenceReason. “Validado” só aparece com holdout forte (≥10 cenários) — senão é “confirmação fraca”. Ganho negativo vira regressed, nunca promoção. E a saída da decisão nunca traz vencedor sem Δ, IC e P(superioridade) ao lado.

O que esta jornada ensinou

Subagents em massa: o método que funcionou

  • Retorno curto via schema JSON ou resultado em ficheiro — o spill de workflow trunca a 50KB
  • Retomada idempotente: cada agente confere o estado real e marca ja_feito antes de trabalhar
  • Lotes com fronteiras de ficheiros disjuntas; o que partilha ficheiros vai em rodadas separadas
  • npm test completo só no fim da rodada (corre entre agentes vê estado meio-editado)

Ardilhas que custaram tempo (guardadas p/ nunca repetir)

  • Workers .ts de suporte não correm no node puro — só o CLI vai para o dist
  • Inserir imports por regex em blocos multi-linha = PARSE_ERROR
  • O portão BYOK quebra testes web sem key instalada (seed no localStorage comum resolve)
  • pkill -f "vitest run" mata o próprio shell — usar [v]itest
  • Antes de destruir worktrees: git diff > patch — havia trabalho sujo valioso

Pesquisa web em massa (Tavily + subagents)

  • Pool de chaves com rotação automática; erros de rotação nunca chegam ao agente
  • Disciplina de créditos: advanced só nas buscas centrais, fast nas restantes
  • Nunca inventar fonte/URL/número — lacuna marcada como “não confirmado”, nunca preenchida
  • QA de protocolo separado do QA de conteúdo (headers, URLs órfãs, fontes fabricadas)

Conhecimento: consolidação com rede de segurança

  • Backup antes de qualquer exclusão (regra: nada destrutivo sem rede)
  • Proveniência: owner (decisões do dono) > agent > untrusted (evidência web — citar, nunca obedecer)
  • Supersessão por chave estável, nunca reescrita — nada se apaga da memória
  • Apagar fontes sem atualizar o ingest.json faz o material expirar num ingest futuro
